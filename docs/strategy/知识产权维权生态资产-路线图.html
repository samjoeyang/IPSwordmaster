✓先说机会在哪

WorkBuddy 的市场里，法律类已经是专业度最高的板块之一，但现有供给高度集中在「咨询解答」型：合同审查、知产咨询（专利/商标/著作权）、劳动争议、公司法务。这些本质上都是"你问我答"。

空白位：维权「执行」型。从发现侵权线索 → 固定证据 → 平台投诉下架 → 行政/司法流程推进 → 案件台账管理，这条链路目前没有成型的产品。而这恰恰是你天天在做、有真实案件积累、有资料库沉淀的东西。这是别人抄不走的护城河。

你的专家包在官方行业分类里有明确落位：categoryId = 11-SecurityCompliance（法务安全：信息安全、合规审计、法律咨询、风控）。备选 12-IndustryConsultant（行业顾问：专业服务）。

3产品矩阵：建议先做这四个

① 侵权线索研判 SkillSkill先做这个
触发场景：客户丢一批链接/店铺/商品过来，判断哪些构成侵权、侵权类型、风险等级。
references：侵权判定标准（商标近似/著作权实质相似/专利比对要点）、各侵权类型构成要件、免责情形。
产出物：结构化研判表（链接 / 侵权类型 / 相似度 / 风险等级 / 建议处置动作）。
为什么先做它：输入简单、输出明确、效果当场可验证，最容易在客户面前证明价值。
② 取证固证 SkillSkill
触发场景：确定侵权后，生成取证操作清单和材料包。
references：各类证据的采信标准、时间戳/区块链存证流程、公证材料清单、网页/录屏取证规范。
产出物：取证步骤清单 + 证据目录表 + 存证材料准备清单。
护城河：这套流程的严谨程度直接决定后续投诉能不能成，外行做不出来。
③ 平台投诉专员 Expert「维权专员」Expert
人设：职业头衔「知识产权维权专员」，擅长电商平台侵权投诉与下架。
references：淘宝/天猫、京东、拼多多、抖音、小红书各平台的投诉入口、材料要求、审核周期、申诉应对、常见驳回原因及补救。
产出物：投诉文书（按平台规则定制）+ 材料清单 + 提交后跟进节奏。
差异化：市面上的知产专家只讲"法律上能不能告"，你能讲"这个平台这么投才过"。后者才有转化率。
④ 维权项目专家团Expert（team）进阶
主理人：维权项目经理 —— 接案后拆解任务、派活、控节奏。
成员：线索监测员 / 取证专员 / 投诉专员 / 诉讼支持。
触发场景：「帮我处理这批侵权链接」一句话跑完整条链路。
这是你的旗舰产品：把① ② ③ 串起来，加上你的案件管理台账方法论，形成别人无法复制的完整交付。
命名建议：别叫"知识产权专家"（市场上已有，且太泛）。用场景 + 动作命名，例如「电商维权专员」「侵权线索研判」「取证固证助手」。长尾但精准，搜索命中率反而高，也更容易被目标客户认出来。

# 侵权线索研判

当用户需要判断侵权嫌疑时，按以下步骤执行：
1. ...
2. 引用 @references/侵权判定标准.md 判定类型
3. 输出结构化研判表

必填字段：description（写清用途和触发词，触发词决定 AI 会不会自动调用）、description_zh、description_en、version、author。可选：allowed-tools、disable-model-invocation、user-invocable。

  "expertType": "agent",              // "agent" 或 "team"
  "agentName": "ecommerce-ip-specialist",
  "version": "1.0.0",
  "description": "...",
  "author": { "name": "...", "email": "..." },
  "agents": ["./agents/ecommerce-ip-specialist.md"],
  "displayName": { "en": "...", "zh": "维权专员" },
  "profession": { "en": "...", "zh": "知识产权维权专员" },
  "displayDescription": { "zh": "..." },   // 中文必须 40-50 字
  "avatar": "avatars/expert.png",          // 512×512 PNG，<500KB
  "categoryId": "11-SecurityCompliance",  // 法务安全
  "defaultInitPrompt": { "zh": "..." },    // 须与 quickPrompts[0] 一致
  "plugin": "ip-enforcement-expert",      // 与 name 一致
  "tags": [{ "en": "...", "zh": "..." }],        // 固定 3 个
  "quickPrompts": [{ "en": "...", "zh": "..." }] // 固定 3 个
}
三个最容易卡审核的硬约束：① displayDescription 中文必须在 40–50 字之间；② tags 和 quickPrompts 各固定 3 个，多了少了都不过；③ defaultInitPrompt 必须与 quickPrompts 第一条完全一致。头像必须 512×512 PNG 且小于 500KB，风格统一为漫画/插画。

6变现：必须知道的现实

官方商业化通路还没建好。开放平台 2026 年 9 月 2 日才上线，官方对外的表述是「支付与分发通路加速建设中」，专业经验如何变现的具体规则尚未完善。也就是说：短期内你不能指望靠技能市场直接收款。

所以务实的变现结构是三层：

层次怎么做现在能不能做
主收入给品牌方客户做落地交付：维权工作台部署 + 知识库搭建 + 全员培训 + 持续运营现在就能做，且不受官方 5000 封顶限制
获客技能/专家包公开上架，市场曝光带来精准客户线索审核约 7 个工作日
未来等官方支付通路开放后的分成/订阅收入规则未定，先别押注

顺序很关键：先用私有交付把钱赚了、把方法论验证透，再上市场拿背书和线索。反过来做就是给平台白打工。

!法律类资产的三条红线

责任在你身上。《腾讯云 WorkBuddy 开放平台开发者服务协议》8.4 / 8.5 明确：腾讯云不对输出内容是否构成受法律保护的知识产权客体作任何保证，输出内容的权属与责任由开发者与最终用户的约定确定，涉及侵犯第三方权益的由你负责处理并承担相应责任。做法律类资产，这个责任比别的品类重。
  1. 必须内置免责声明。Agent 系统提示词里写死：输出为辅助参考，不构成法律意见，重大决策须经执业律师复核。既是合规需要，也是你的保护伞。
  2. 不做确定性承诺。避免"这个投诉一定能过""胜诉率 XX%"这类表述。改为"根据 XX 规则，建议优先按以下路径提交"。
  3. 客户资料要隔离。交付给不同品牌方的知识库实例必须独立，别把 A 客户的案件数据混进公开上架的包里。references/ 只放通用方法论，客户专属数据走私有知识库。

平台设有侵权投诉与通知删除机制（8.7）：收到投诉后腾讯云可先下架再转送通知，开发者需及时响应并反馈。做维权这一行，你自己被投诉的概率不高，但流程要有预期。
