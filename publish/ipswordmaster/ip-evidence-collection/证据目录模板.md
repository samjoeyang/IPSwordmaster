# 取证操作清单与证据目录（输出模板）

> 输出时严格使用以下三段结构。**取证操作清单在前**——先让人知道该做什么，
> 再用目录表做归档。缺失项填「待取」，不得编造证据内容。

## 一、取证前提（先确认，再动手）

| 项目 | 内容 |
| --- | --- |
| 取证目的 | 平台投诉 / 律师函 / 行政投诉 / 民事诉讼 / 刑事报案 |
| 对应强度 | 低 / 中 / 中高 / 高 / 最高 |
| 建议固证方式 | 时间戳 / 区块链存证 / 公证 / 购买公证 |
| 关联线索 | 来自侵权线索研判的序号（如 #1、#2、#10） |
| 是否已固证 | **若否，先提示：任何对外动作前必须先固证** |

## 二、取证操作清单

按「先固定易消失的，后补充稳定的」排序输出：

| 步骤 | 动作 | 取证对象 | 固证方式 | 注意事项 |
| --- | --- | --- | --- | --- |
| 1 | 立即固定 | 商品页 / 帖子内容 | 时间戳或区块链存证 | 内容随时可能被删除，**优先做** |
| 2 | 固定详情 | 详情图、规格、SKU | 同上 | 侵权要素常在详情图里 |
| 3 | 记录要素 | 完整 URL、取证时间 | 截图须含 URL 栏与时间 | 裁剪 URL 会削弱证明力 |
| 4 | 主体核查 | 店铺主体工商信息 | 工商公示截图 + 存证 | 缺主体证据将无法指向责任方 |
| 5 | 按需购买 | 实物商品 | 购买公证 + 实物封存 | 价格异常、需证明实物侵权时 |
| 6 | 编号归档 | 全部证据 | 按编号规则 | 回填台账 |

**按渠道类型补充的专项动作**（据线索实际情况增删）：
站内电商 → 店铺主体、用户评价实物图 ｜ 站外社交 → 引流去向 ｜ 二手闲置 → 是否标注「自用/闲置」（关系权利用尽）
源头批发 → 贴牌/定制表述、工厂实景 ｜ 独立站跨境 → WHOIS、支付与托管 ｜ 线下档口 → 现场影像、交易凭证

## 四、证据链条完整性检查

逐项核对，缺哪项标红提示：

| 环节 | 是否齐备 | 缺失后果 |
| --- | --- | --- |
| 权利证据（注册证/登记证书 + 有效期） | | 投诉无法受理 |
| 侵权证据（被诉页面 + 使用方式） | | 无的放矢 |
| 主体证据（实际经营者） | | 无法指向责任方 |
| 规模证据（销量/价格/时长） | | 索赔缺乏依据 |
| 对比证据（正品与被诉品并列） | | 近似度不直观 |

## 六、结尾固定声明

> 本清单为取证工作的操作准备参考，不构成法律意见。证据能否被采信最终由平台、
> 行政机关或法院个案认定。重大案件须由具备执业资格的专业人员确定取证方案。
> 取证过程必须合法，不得以欺诈、侵入系统或非法获取个人信息的方式取得证据。
